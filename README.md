# Mathématiques — du primaire au master

Une collection de cours en français, écrite en LaTeX : définitions, exemples
expliqués, démonstrations, exercices et corrigés. Le fichier
[`mathscommun.sty`](commun/mathscommun.sty) définit la présentation de tous les documents.

L'objectif à terme est un **niveau master de mathématiques**, construit
progressivement après la terminale par la licence puis le master :
calcul maîtrisé, définitions précises, preuves, contre-exemples et autonomie.
Les compléments avancés restent distingués du programme obligatoire.

Le référentiel [OBJECTIFS.md](OBJECTIFS.md) guide toute création et révision.
Les PDF sont disponibles dans les [releases](https://github.com/yilas/maths/releases)
après la première publication sur tag contenant ce workflow.

## Organisation et progression

Le parcours prévu est le suivant. Seuls les niveaux rédigés ont un dossier :

| Étape | Dossier | Classes prévues, dans l'ordre |
| --- | --- | --- |
| Primaire | `sources/01-primaire/` | `01-cp`, `02-ce1`, `03-ce2`, `04-cm1`, `05-cm2` |
| Collège | `sources/02-college/` | `01-sixieme`, `02-cinquieme`, `03-quatrieme`, `04-troisieme` |
| Lycée | `sources/03-lycee/` | `01-seconde`, `02-premiere`, `03-terminale` |
| Licence | `sources/04-licence/` | `01-l1`, `02-l2`, `03-l3` |
| Master | `sources/05-master/` | `01-m1`, `02-m2` |

Chaque classe conserve quatre maîtres LaTeX : **guide, cours, exercices et corrigés**.
Les chapitres, programmes Python et données restent à côté de ces maîtres.
Le style unique est dans `commun/mathscommun.sty` ; les modèles sont dans `modeles/`.
`niveaux.json` déclare le chemin et le suffixe des maîtres pour chaque niveau disponible.
Ajouter une entrée à ce catalogue intègre le niveau à la compilation, aux contrôles
et aux releases. Ne déclarer un niveau qu'avec ses quatre documents prêts à compiler.
Les identifiants de niveau doivent rester uniques, sans espace ni slash.

## Compiler dans GitHub Codespaces

Dans GitHub : **Code → Codespaces → Create codespace on main** (ou sélectionner
la branche de cette PR pour l'essayer avant fusion). La première ouverture construit
l'environnement LaTeX et Python ; les suivantes le réutilisent. La configuration
fonctionne aussi avec VS Code et **Dev Containers: Reopen in Container** en local.

Depuis le terminal à la racine :

```sh
make pdf                       # toutes les classes disponibles
make pdf NIVEAU=premiere        # les quatre documents d'une classe
make verifier                  # compilation, tests Python et contrôles de rendu
make release                   # mêmes contrôles + préparation des fichiers de release
python3 compiler.py --niveau seconde --chapitre 9
python3 compiler.py --document modeles/modele_nouveau_cours.tex
```

Les quatre PDF de chaque classe sont dans `build/pdf/<niveau>/`. Pour les lire,
ouvrir un PDF dans l'éditeur ; pour le récupérer, utiliser **Download** dans
l'explorateur du Codespace. LaTeX Workshop permet aussi de compiler le maître
ouvert avec la recette « pdfLaTeX avec style commun ». Ses sorties sont séparées
dans `build/editeur/` ; la vérification officielle passe par `make verifier`.
Arrêter le Codespace après usage pour ne pas le laisser fonctionner inutilement.

Hors conteneur, installer Python 3, Make et les paquets listés dans
[le Dockerfile](.devcontainer/Dockerfile). La compilation seule ne nécessite que
Python et LaTeX ; les contrôles de rendu utilisent Poppler, PyMuPDF et Pillow.
Le compilateur ajoute `commun/` à `TEXINPUTS`, effectue trois passages et refuse
les références non résolues ou les débordements. Il fonctionne depuis tout dossier.

## PDF et releases

Aucun PDF n'est versionné. Les anciennes versions restent dans l'historique Git.
Une PR construit l'environnement Codespaces, compile tous les niveaux, exécute les
tests Python disponibles et contrôle le rendu. Ses PDF et aperçus restent accessibles
14 jours dans les artefacts GitHub Actions.

Après fusion, créer et pousser un **nouveau tag sur un commit contenant le workflow** :

```sh
git switch main
git pull --ff-only
git tag -a v1.0.0 -m "Collection de mathématiques v1.0.0"
git push origin v1.0.0
```

Choisir un nom encore inutilisé. Tous les noms de tags déclenchent le workflow,
pas seulement `v*`. Un tag uniquement local ne déclenche rien ; pousser les tags
un par un. La publication utilise le commit exact du tag. Un tag créé par un autre
workflow avec `GITHUB_TOKEN` ne déclenche pas normalement ce second workflow :
utiliser ici le push authentifié du contributeur.

La release contient `troisieme-cours.pdf`, `seconde-guide.pdf`, etc., et
`maths-tous-les-niveaux.zip`, organisé en `<niveau>/<document>.pdf`.
Elle n'est rendue publique qu'après tous les contrôles et l'envoi des fichiers.
Si l'envoi échoue, elle reste en brouillon : relancer le job permet de terminer.
Une release déjà publiée n'est pas modifiée lors d'une relance ; publier un nouveau
tag pour une correction. La validation des PR reste en lecture seule ; seul le
job de publication sur tag dispose du droit d'écriture.
